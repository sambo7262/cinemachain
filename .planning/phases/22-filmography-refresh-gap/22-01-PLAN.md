<objective>
Land the schema and on-demand TTL self-heal that makes actor filmographies refresh themselves
when stale. This plan covers STALE-02 end-to-end at the data layer + routing layer:

1. Alembic migration 0019 adds a nullable `filmography_fetched_at TIMESTAMP` column on `actors`
   (no backfill — NULL semantically = "stale" so the self-heal kicks in lazily).
2. `Actor` SQLAlchemy model gets the new mapped column.
3. `_ensure_actor_credits_in_db` is extended with a `force_refresh: bool = False` parameter and
   a 14-day TTL check. When the actor's `filmography_fetched_at` is NULL or older than the TTL
   (or when `force_refresh=True`), the existing fetch path runs synchronously. When it's within
   the TTL and `force_refresh=False`, the existing short-circuit fires (no TMDB call).
4. On the success path that already sets `filmography_fetched=True` (line ~504 in game.py),
   we now also set `filmography_fetched_at = datetime.utcnow()` in the same transaction.
5. Targeted pytest cases cover all four TTL branches.

Purpose: STALE-02 is the surgical fix that unblocks every active game session post-deploy.
Once this ships, the next click on a stale actor re-fetches their filmography from TMDB
synchronously, surfacing new releases like Devil Wears Prada 2 immediately.

Output: Migration + model column + extended helper + tests. Backend layer ready for plan 22-02
to wire `force_refresh=True` into the nightly job and add the manual refresh endpoint.

    tmdb: TMDBClient,

    vote_threshold: int = 5,
    # NEW (this plan): force_refresh: bool = False

    actor_row = await db.execute(select(Actor).where(Actor.tmdb_id == actor_tmdb_id))
