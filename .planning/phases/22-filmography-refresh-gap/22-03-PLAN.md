<threat_model>
**Threats considered for Plan 22-03:**

1. **TMDB rate limit abuse from button mashing.** Mitigation: the button is disabled while
   `cacheRunning` is true, the backend `_cache_state.running` guard (Plan 22-02) prevents
   concurrent runs even if the disable state is bypassed (e.g., via React DevTools), and
   the polling effect re-enables the button only after the backend reports `running=false`.
   Worst case if all client-side guards fail: the backend returns `{running: true}` on every
   POST until the in-flight pass completes — no extra TMDB load.

2. **Manual refresh endpoint discoverability.** This phase intentionally exposes the endpoint
   in Settings (per Decision 5 — belt-and-suspenders user lever). The backend is not publicly
   reachable (Tailscale-fronted on Synology NAS per STATE.md). No CSRF token is added because
   the entire app is a same-origin SPA behind nginx; existing CSRF posture from prior phases
   carries over (no other mutation endpoint uses CSRF tokens — see Phase 21 settings-validate
   endpoint as analog).

3. **Secret leakage in client logs.** No API keys touch this code path. The endpoint response
   is `{started: true} | {running: true}` — no credential material. `apiFetch` already handles
   error response bodies; the `catch {}` block silently swallows errors so no error response
   body lands in console.error or DOM. Settings.tsx does not log the response.

4. **Visual confusion from shared "Last run:" timestamp.** Both endpoints update the SAME
   `_cache_state.last_run_at` field, so "Last run:" reflects whichever ran most recently.
   This is intentional (Decision 5 — "Reuses the existing cache-refresh button pattern... Same
   visual feedback") but means the user cannot distinguish "Last TMDB cache run" from "Last
   actor refresh run." Acceptable for a single-user app where the user always knows which
   button they just clicked. If this proves confusing in practice, split into per-endpoint
   state in a follow-up; out of scope for this phase.
</threat_model>
